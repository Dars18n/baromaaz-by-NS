# Baromaaz — Har Mahina, Naya Libaas

The e-commerce website for **Baromaaz**, a handcrafted Indian ethnic-fusion label from Jaipur with a new limited collection every month.

Built with **Next.js 15 (App Router) + Tailwind CSS**. Every page is pre-rendered as HTML with its own title, description, canonical tag and Open Graph image, so links preview properly on WhatsApp, Instagram and Google.

---

## 1. Run it on your computer

You need **Node.js 20 or newer** (https://nodejs.org).

```bash
npm install
npm run dev          # open http://localhost:3000
```

Production build:

```bash
npm run build
npm start
```

## 2. Go live (recommended: Vercel, free tier works)

1. Push this folder to a GitHub repository.
2. Import it at https://vercel.com/new — it detects Next.js automatically.
3. Add the environment variables from `.env.example` in *Project → Settings → Environment Variables*.
4. Connect your domain (e.g. `baromaaz.com`) under *Settings → Domains*, and set `NEXT_PUBLIC_SITE_URL` to it.

Any Node.js host (Hostinger VPS, Render, Railway, AWS) also works with `npm run build && npm start`.

## 4. Products

All products live in **`src/data/products.json`**. Each product:

```json
{
  "slug": "zari-brocade-corset",          // URL: /product/zari-brocade-corset
  "name": "Zari Brocade Corset",
  "category": "corsets",                  // tops | kurtis | corsets | dresses | co-ord-sets | festive
  "price": 1799, "mrp": 2499,             // discount % is calculated automatically
  "color": "Black & Gold",
  "fabric": "Banarasi brocade",
  "sizes": ["XS","S","M","L"],            // optional, defaults to XS–XL
  "added": "2026-10-27",                  // used for "New In" and "Newest" sorting
  "drop": true,                           // part of this month's Monthly Drop
  "mostWanted": true,                     // appears in the Most Wanted tab
  "description": "..."
}
```

Each product needs three images: `public/images/products/<slug>-1.webp` (front), `-2.webp` (alternate), `-3.webp` (detail). Prices always display as `₹1,299`.

**Monthly Drop each month:** set `"drop": true` on the new pieces, `false` on last month's, and update `drop` in `src/lib/site.js`.

## 5. Images

The current images are **illustrated placeholders** (generated by `scripts/generate-placeholders.mjs`). To use real photos:

1. Create a `photos-src/` folder mirroring `public/images/` names, e.g. `photos-src/products/zari-brocade-corset-1.jpg`.
2. Run `npm run images`.

This produces WebP files ~1000 px wide, each under 200 KB, plus 1200×630 JPEG share images for WhatsApp previews (`public/images/og/`). Share images are JPEG on purpose: WhatsApp doesn't reliably render WebP previews. Every other image is WebP and lazy-loaded.

## 6. Reviews

Customers write reviews directly on each product page (rating, name, text, up to 3 photos stored in the existing `product-images` bucket under `reviews/`). They are saved to the Supabase `reviews` table as **pending** and only appear on the site after you approve them: Supabase → Table editor → `reviews` → tick `is_approved` on the row (the site refreshes within the catalogue cache window). Star ratings and `schema.org` review data are calculated from approved reviews only.

## 7. Payments (Razorpay)

1. Get your keys at https://dashboard.razorpay.com/app/keys (start with **Test mode**).
2. Copy `.env.example` to `.env.local` and fill in `NEXT_PUBLIC_RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`.
3. Restart the server.

How it works: `/api/razorpay/order` **recalculates the amount on the server** from `products.json` (so prices can't be tampered with), creates a Razorpay order and opens Razorpay Checkout (UPI, cards, netbanking, wallets). `/api/razorpay/verify` checks the payment signature.

Without keys, checkout runs in **demo mode**: orders are recorded as "Test order — payment not taken".

**Still needed for real orders:** save confirmed orders somewhere you'll see them (database, Google Sheet, or an email to yourself). There's a `TODO` in `src/app/api/razorpay/verify/route.js` for this. Also set up a Razorpay webhook as a backup.

## 9. Accounts, cart, wishlist

The cart, wishlist, profile, order history and return/exchange requests are stored in the shopper's browser (localStorage). Return/exchange requests are also sent to you through a pre-filled WhatsApp message. For logins that sync across devices, add an auth provider later (e.g. Clerk, Supabase Auth or NextAuth with phone OTP).

## 10. SEO & accessibility checklist (done)

- Clean URLs: `/shop`, `/shop/kurtis`, `/product/<slug>`, `/about`, `/drop`, `/new-in`, no `#/` routes
- Per-page `<title>`, meta description, canonical, Open Graph + Twitter image
- `sitemap.xml` (with image entries) and `robots.txt` (generated)
- `schema.org` Product (price, availability, shipping, returns), BreadcrumbList, ClothingStore
- One `<h1>` per page, alt text on every image, aria-labels on icon buttons, skip link, keyboard-friendly tabs and dialogs, WCAG-AA colour contrast
- Mobile-first; tested at 320, 360, 390, 768, 1024 and 1440 px with no horizontal scrolling
